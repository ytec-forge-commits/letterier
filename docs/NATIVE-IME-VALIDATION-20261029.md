# 2.1.0 縦書き入力と編集改善の確認

2026-10-29。合成文書を使用し、Windows実機のディスプレイ1で確認した。開発用アプリ識別子・保存先・WebView2プロファイルを製品版と分離し、通常の利用者文書を開かずに検証した。

## 実装と確認

- 縦書き本文をWindows TSFのITextStoreACPへ接続し、VerticalWritingとOrientation属性を通知する。MS-IMEの標準候補欄が縦書きで表示され、予測・通常変換・選択・確定・取消・連続入力・Undo/Redoを実キーで確認した。
- Google日本語入力では標準の候補インターフェイスを取得できる通常変換とTab展開後の予測候補だけを、Windows RichEditの縦書き候補欄に表示する。クリック確定、確定後の連続入力、候補の次ページ移動と2ページ目の候補確定を確認した。文字列を試作時の8候補・15文字で切り捨てず、9候補ずつのページとスクロールを使う。
- Googleの自動サジェスト欄は標準インターフェイスから候補列を取得できず、標準の横書き表示を維持する。文字箱とネイティブ接続失敗時は既存の入力方式を使う。
- 未確定文字は一時DOMで表示し、確定まで文書・保存・履歴へ混入させない。古い接続からの遅延イベントを無視する。変換中はUndo/Redoを一時無効化する。
- ネイティブ入力へのフォーカス移動と、ツールバーなどへの移動を区別する。文字座標はDOMから取得し、変換対象文節の強調も反映する。MS-IME実機で強調の表示と確定時の解除を確認した。
- コピー失敗時の切り取りは本文を保持する。Ctrl+Backspace/Delete、PageUp/Downと制御文字除外を処理する。Ctrl+Backspaceとページ移動を実キーで確認した。

## テスト結果

| 確認 | 結果 |
|---|---|
| TypeScript・version整合 | PASS |
| 単体テスト | 432 PASS |
| Rust／Windows側テスト | 23 PASS |
| 実アダプターを使うブラウザー境界テスト | 7 PASS（確定、取消、古い接続、絵文字、フォーカス、座標、文節強調） |
| 配布用フロントエンドの回帰テスト | 22 PASS（一括書式、Undo/Redo、読み返し、IME、文字箱、フォント通知、保存回復、テンプレート等） |
| クリップボード失敗・DEL混入のC++回帰テスト | PASS（OS失敗を試験用に代替し、本番の入力処理を実行） |
| Windows WebView2の実PDF出力 | 横書き・縦書き各2ページを出力し、画像と文字情報を確認 |

ページ番号は両書字方向とも、下中央に横向きのアラビア数字「1」「2」として出力された。複数桁の「12」も単体テストで確認した。実プリンターからの紙への出力は今回実施していない。

ツールバー折りたたみと読み返し表示は本文・印刷寸法・保存形式を変更しない。1280×720では通常の編集領域1136×474に対し、折りたたみ時1136×587、読み返し時1280×634を確認した。日本語・英語・狭い表示幅の確認は読み返し表示の検証記録に保存している。

独立した読取レビューで見つかった切り取り失敗、単語削除、変換後方の座標、候補ページ送り、PageUp/Downを修正し、修正後の再レビューを受けた。

## 制約と公開工程

実機のIME挙動はWindows 11の当該環境で確認したもので、すべてのWindows・IMEバージョン、支援技術、実プリンターの動作保証ではない。Windows 10の再実機試験、WACK、Store審査の合格を意味しない。専用のCodex Securityスキャンは未実施。

2.0.1は既に公開済みのため、今回の機能更新は2.1.0として準備する。最終バイナリとMSIXの識別・検査結果、GitHub更新、Store提出の事実は各工程の記録で別に確認し、ローカル試験を公開・提出済みと扱わない。
